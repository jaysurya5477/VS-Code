How to wire this to ABAP CDS + OData V4 and Fiori

1. Never send rows to the browser — aggregate in HANA

With 100+ plants and thousands of materials, the client must only ever receive the aggregate it is about to draw. Every chart on this page maps to exactly one $apply request. Open the Query inspector (bottom right) to see the URL each chart would fire.

2. CDS analytical stack

@AbapCatalog.viewEnhancementCategory: [#NONE]
@AccessControl.authorizationCheck: #CHECK
@EndUserText.label: 'Plant & Material Sales — Cube'
@Analytics.dataCategory: #CUBE
@Analytics.internalName: #LOCAL
define view entity ZI_PlantMaterialSalesCube
  as select from I_BillingDocumentItemCube as bi
  association [0..1] to I_Plant     as _Plant    on  _Plant.Plant = bi.Plant
  association [0..1] to I_Product   as _Product  on  _Product.Product = bi.Material
{
      @ObjectModel.foreignKey.association: '_Plant'
  key bi.Plant,
  key bi.Material,
  key bi.FiscalYearPeriod,
      _Plant.PlantName,
      _Product.ProductGroup            as MaterialGroup,
      bi.SalesOrganization,
      bi.BaseUnit,

      @Semantics.amount.currencyCode: 'TransactionCurrency'
      @Aggregation.default: #SUM
      bi.NetAmount,

      @Semantics.quantity.unitOfMeasure: 'BaseUnit'
      @Aggregation.default: #SUM
      bi.BilledQuantity,

      @Semantics.amount.currencyCode: 'TransactionCurrency'
      @Aggregation.default: #SUM
      bi.CostAmount,

      bi.TransactionCurrency,
      _Plant,
      _Product
}

On top of the cube, expose a query view. @Analytics.query: true is what makes the OData V4 service accept $apply:

@Analytics.query: true
@OData.hints.groupingOnBaseLevel: true
define transient view entity ZC_PlantMaterialSalesQry
  provider contract analytical_query
  as projection on ZI_PlantMaterialSalesCube
{
  @AnalyticsDetails.query.axis: #ROWS
  Plant,
  PlantName,
  Material,
  MaterialGroup,
  FiscalYearPeriod,
  @AnalyticsDetails.query.axis: #FREE
  SalesOrganization,
  @AnalyticsDetails.query.axis: #COLUMNS
  @DefaultAggregation: #SUM
  NetAmount,
  @DefaultAggregation: #SUM
  BilledQuantity,
  @DefaultAggregation: #SUM
  CostAmount,
  BaseUnit,
  TransactionCurrency
}

Then a service definition + V4 service binding (ODataV4 · UI). Publish and note the resulting URL — that is what goes into CONFIG.serviceUrl at the top of the script in this file.

3. The request each chart fires

-- Top plants bar chart
GET {service}/ZC_PlantMaterialSalesQry
    ?$apply=filter(FiscalYearPeriod ge '2025008' and FiscalYearPeriod le '2026007')
           /groupby((Plant,PlantName),
                    aggregate(NetAmount with sum as NetAmount,
                              BilledQuantity with sum as BilledQuantity))
    &$orderby=NetAmount desc
    &$top=20
    &$count=true

-- Trend line (period × plant), only the plants already known to be top 5
GET {service}/ZC_PlantMaterialSalesQry
    ?$apply=filter(Plant in ('1000','1010','1020','1030','1040'))
           /groupby((FiscalYearPeriod,Plant),aggregate(NetAmount with sum as NetAmount))
    &$orderby=FiscalYearPeriod asc

-- Heatmap (plant × material group)
GET {service}/ZC_PlantMaterialSalesQry
    ?$apply=groupby((Plant,MaterialGroup),aggregate(NetAmount with sum as NetAmount))

-- Scatter / detail list — always paged, never unbounded
GET {service}/ZC_PlantMaterialSalesQry
    ?$apply=groupby((Plant,Material),
                    aggregate(NetAmount with sum as NetAmount,
                              BilledQuantity with sum as BilledQuantity))
    &$orderby=NetAmount desc&$top=5000&$skip=0

4. Volume rules that actually matter here

  • Cap the cardinality before it reaches the chart. A scatter of every plant–material pair is ~105 points. Always request $orderby=NetAmount desc&$top=5000 and label the chart as "top 5,000 by value" — nobody can read the tail anyway.
  • Charts get aggregates, the table gets pages. The detail table below uses server-side paging ($top/$skip or the UI5 growing feature), never a full load.
  • Filter before group. In $apply the filter(...) transformation must come first in the pipeline so HANA prunes partitions before aggregating.
  • Push the "top N" into the query. groupby(...)/topcount(20,NetAmount) is supported by the analytical runtime and keeps the payload tiny.
  • Cache dimension lists. The 128 plants and 12 material groups feeding the value helps come from separate small entity sets, loaded once, not from the fact query.
  • Turn animation off on any ECharts series above ~2,000 points, and set large:true plus progressive — already done in this file.

5. Embedding in Fiori Elements / freestyle UI5

  • Freestyle is the simplest host: an sap.m.Page with an sap.ui.comp.smartfilterbar.SmartFilterBar bound to the same entity set, and one sap.ui.core.HTML control per chart. Call echarts.init() in onAfterRendering, dispose in onExit.
  • In Fiori Elements, add the charts through a custom section (manifest.json → controlConfiguration → …/@com.sap.vocabularies.UI.v1.Facets → custom fragment). The FE filter bar's search event gives you the filter array — convert it to the $apply filter string.
  • Re-render on resize: sap.ui.Device.resize.attachHandler(() => chart.resize()).
  • Fiori theming: read sap.ui.core.theming.Parameters.get() for sapChart_OrderedColor_1…11 and feed them into the ECharts color array so charts follow the user's theme, including high-contrast.
  • Accessibility: ECharts canvas is opaque to screen readers. Keep the detail table on the page as the accessible equivalent, and set aria: {enabled:true, decal:{show:true}} so series are distinguishable without colour.
